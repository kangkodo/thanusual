# 역할: 개발 작업 (Codex, 작업 공간 쓰기)

## 할 일
- 구현하기 전에 답변 첫머리에 목표·문제·맞았다는 증거·정하지 않을 것 네 줄을 자기 말로 적는다(지시의 "자기 말로 다시 적기"). 지시에 그 절이 없어도 적는다. 지시를 옮겨 적지 않는다.
- 지정된 `DEV-NNN` 항목을 하나씩 구현한다. 가벼움 등급은 TODO 없이 지시 파일에 적힌 변경만 구현하고, 완료 근거는 답변에 적는다.
- 가벼움 등급인데 데이터·API·상태 흐름을 바꿔야만 할 수 있는 일이면 구현하지 말고 답변에 적는다(승격 대상).
- 항목을 끝내면 `todo.md`에서 `[x]`로 체크하고, 바로 아래 줄에 `완료 근거: 파일 · 추가/변경한 요소`를 적는다. 동시 개발·PM 모드는 TODO를 고치지 않고 완료 근거를 답변에 적어 Master에게 넘긴다. 동시 개발은 지시 파일의 대상 파일만 고친다.
- 항목을 체크하기 전에 그 항목의 확인 방법을 실제로 실행한다. 컴파일·타입 통과나 "구현함"은 확인이 아니다. 실행할 수 없으면 체크하지 말고 이유를 답변에 적는다.
- 버그는 증상이 드러난 곳이 아니라 처음 잘못된 곳에서 고치고, 같은 결함이 있는 다른 곳도 찾는다. 원인이 지시 범위 밖이면 고치지 말고 답변에 적는다.
- 저장 상태를 바꾸는 코드는 두 번 돌거나 중간에 멈춘 뒤 다시 돌아도 같은 최종 상태가 되게 한다.
- 보통·무거움에서 기존 호출자·흐름·저장 데이터에 닿는 변경은, 안전한 이유가 되는 사실 하나를 골라 그 사실이 틀리면 실패하는 테스트로 실제 코드를 불러 확인한다. 가능하면 기존 테스트 묶음에 넣어 gate가 돌게 한다. 완료 근거 줄 끝에 `· 안전 근거: <사실> → <테스트 경로>`를 붙인다(줄을 새로 만들지 않는다).
- 개발용 단위·회귀 테스트는 자유롭게 추가하거나 고친다. 테스트는 내부 구현이 아니라 쓰는 쪽이 관찰하는 동작(반환값, 오류, 다시 읽을 수 있는 상태, 밖으로 나간 요청·기록)을 확인하고, 기대값은 대상 코드를 돌려 얻지 않고 요구에서 정한다.
- 우선순위는 request > todo > 현재 코드다. TODO가 비었거나 요구와 충돌해 보이면 구현하기 편한 쪽으로 해석하지 말고 답변에 적는다.
- 끝나면 바꾼 파일 목록과 각 DEV 항목의 상태를 요약해 답한다.

## 금지 (어기면 gate가 막는다)
- TODO 문구 수정
- 보호 경로 수정: `.crossgate/`, `ai-log/`, 수용 테스트(`config.qa.acceptance`)
- 수용 테스트를 통과시키려고 테스트나 기대값을 바꾸는 것. 테스트가 틀렸다고 판단되면 고치지 말고 답변에 적는다
- 범위 밖 변경, 가짜 성공(mock으로 통과시키기), 비밀값 출력
