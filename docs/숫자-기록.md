# 숫자 기록 (PostHog)

jelly-studio의 숫자 기록 약속 사본이다. 이 서비스의 개발은 이 약속을 따른다.

## 이 서비스의 값

- `service` 값: `thanusual` — 모든 이벤트에 붙인다.
- 핵심 행동(`core_action` 이벤트의 `action` 값): `place_open`

## 평소보다

2026-10-03에 `/crossgate`로 넣었다(실행 기록 `ai-log/20261003/001_004527_posthog-tracking`). 아래는 지금 동작이고, 굵은 글씨는 그 실행에서 사용자가 정한 결정이다.

- 불러오기: `analytics.js`가 PostHog 공식 로더를 실행하고 `index.html`, `404.html`이 둘 다 이 파일을 불러온다. 브라우저 수집 주소는 `https://us.i.posthog.com`이다. `https://us.posthog.com`은 화면과 조회 API 주소다(jelly-studio가 쓴다). 공개 키와 주소는 비밀이 아니라 코드에 있다. 개인 API 키(`phx_`)는 이 저장소에 넣지 않는다.
- 불러오지 않는 경우: 공개 키가 비었을 때, 호스트가 `localhost`·`127.0.0.1`·`[::1]`일 때(**개발 트래픽을 운영 숫자에 섞지 않는다**), 브라우저에서 쿠키가 차단돼 있을 때(**고지의 "쿠키 차단"이 실제로 수집 중단이 되게 한다**). 이때는 PostHog로 가는 요청도 쿠키도 없다. 그 밖의 주소(운영, Pages 미리보기, 나중에 붙일 도메인)에서는 보낸다.
- 보내는 이벤트는 셋뿐이다: `$pageview`, `core_action`, `$exception`. 클릭 자동 수집, `$pageleave`, 세션 녹화, 설문, 히트맵, 죽은 클릭, 성능 지표는 초기화 설정에서 꺼 둔다. 가입·결제·AI가 없으므로 `signup`·`purchase`·`ai_cost`는 없다.
- `$pageview`는 페이지를 불러올 때 한 번 나간다. 장소 선택으로 주소의 `#p=`가 바뀌는 것은 페이지뷰가 아니다. 초기화에 PostHog의 `defaults` 날짜를 주면 주소 변경마다 페이지뷰가 나갈 수 있어 주지 않는다.
- `service=thanusual`은 PostHog `loaded` 콜백에서 전역 속성으로 등록한다. 첫 `$pageview`보다 먼저라서 첫 이벤트에도 붙는다. jelly-studio는 `service`로 묶어 세므로, 첫 `$pageview`에 `service`가 빠지면 방문자 수가 0으로 나온다.
- `core_action`(`action=place_open`)은 사용자가 앱 안에서 장소를 골라 **선택한 장소가 바뀔 때만** 1건 나간다: 목록 행(순위 목록, 「고정한 장소」)을 누르기·클릭·키보드로 고를 때, 지도의 점·핀을 고를 때, 상세의 「가까운 다른 장소」를 고를 때. 이미 열려 있는 장소를 다시 고르면 세지 않고, 닫았다가 다시 열면 센다. 주소(`#p=`)로 복원된 장소(첫 로드, 주소 변경), 자동 새로고침, ☆ 고정·해제, 닫기, 분류 탭·검색·시간 모드·레이어 조작은 세지 않는다. 속성은 `service`, `action`뿐이고 장소 이름은 넣지 않는다.
- `$exception`은 PostHog 기본 범위(잡히지 않은 오류, 거부된 Promise)의 메시지와 스택이다.
- 주소 자르기: **모든 이벤트에서 주소 형태의 값(`http://`·`https://`로 시작하는 문자열)은 `?`와 `#` 뒤를 잘라 보낸다.** 임의 쿼리, 장소 이름(`#p=`), 리퍼러의 검색어가 나가지 않는다. 404의 경로는 깨진 링크를 찾는 데 쓰려고 그대로 둔다.
- 개인정보를 보내지 않는다. 검색어는 어떤 이벤트에도 들어가지 않고 `identify`를 부르지 않는다. 방문자는 익명이다.
- 쿠키 고지: `index.html` footer의 접힌 안내에 아래 "쿠키 고지 문구 예시"를 그대로 넣었고, 제목은 「데이터 출처와 한계 · 쿠키 안내」다. **폰에서는 목록 시트를 펼쳤을 때 맨 아래에 footer가 보인다**(접은 시트에서는 보이지 않는다). **`404.html`에는 고지를 넣지 않는다.** 고지는 서비스 단위이고 404는 첫 화면으로 가는 링크를 둔다. 동의 배너와 거부 버튼은 만들지 않는다.
- PostHog를 못 불러오거나 전송이 실패해도 앱은 그대로 동작한다. 기록 호출은 `window.posthog`가 없으면 조용히 넘어간다.
- `_headers`에는 외부 스크립트를 막는 설정이 없어 금지 경로를 바꾸지 않았다.

### 확인 방법

- 배포 뒤 실제 수집: jelly-studio 루트에서 `python3 bin/jelly resume thanusual`을 돌려 방문자 수가 0보다 큰지 본다. 운영 화면을 한 번 열고 몇 분 뒤에 본다. 0이면 PostHog 화면에서 `$pageview`에 `service`가 있는지부터 본다.
- 병합 전 확인은 자동 검사(`tests/acceptance/analytics.test.js`)와, 전송을 가로챈 실제 SDK 확인으로 했다. 기록은 `ai-log/20261003/001_004527_posthog-tracking/03-qa/`에 있다.
- 로컬에서 실제 SDK를 볼 때의 함정 둘:
  - `http://thanusual.localhost:<포트>/`처럼 `*.localhost`로 열면 로컬 목록에 없어서 PostHog가 뜨고 **실제로 전송한다**. 확인할 때는 `us.i.posthog.com`으로 가는 요청을 가로채서 막는다. 평소 개발은 `localhost`나 `127.0.0.1`로 연다.
  - posthog-js는 봇으로 보이는 브라우저의 이벤트를 조용히 버린다. 헤드리스 Chromium이 여기에 걸려서, 설정이 맞아도 이벤트가 하나도 안 나간다. 고장이 아니다.

### 배포 전 운영자 확인

PostHog 계정 쪽 설정은 저장소 밖이라 코드로 보장하지 못한다. 배포 전에 운영자가 확인한다(진행 상태는 [인수인계](인수인계.md) "다음 할 일").

- 방문자 IP 저장 끄기(프로젝트 설정의 Discard client IP data). 어떤 요청이든 IP는 전달되고, 저장할지는 이 설정이 정한다.
- 무료 한도를 넘어도 추가 과금 없이 수집이 멈추는 상태인지(결제 설정). 프로젝트 하나를 jelly-studio 서비스 전체가 같이 쓴다. 한도에 닿으면 기록이 멈추고 그동안의 숫자 누락을 허용한다. 다음 달 한도가 돌아오면 다시 기록된다.

## 1. 구성

- PostHog 프로젝트 하나에 jelly-studio의 모든 서비스를 기록한다.
- **모든 이벤트에 `service` 속성(= 서비스 id)을 붙인다.** 브라우저에서는 전역 속성으로 등록하고, 서버에서 보내는 이벤트에는 직접 넣는다.
- 방문자 구분은 쿠키를 쓴다(PostHog 기본 저장 방식). 같은 사람의 재방문과 사용 흐름까지 본다.
- 그래서 PostHog를 넣는 서비스는 사용자에게 보이는 곳(개인정보 처리방침, 없으면 화면 하단 안내)에 다음을 알린다: 이용 통계를 위해 쿠키를 쓴다는 것, 모으는 것은 익명 이용 기록이고 개인정보는 모으지 않는다는 것, 통계 도구(PostHog, 해외 서버), 거부 방법(브라우저에서 쿠키 차단). PostHog를 처음 넣는 개발에서 함께 넣는다.

### 쿠키 고지 문구 예시

> 이 서비스는 이용 통계를 위해 쿠키를 사용합니다. 모으는 것은 익명 이용 기록뿐이며, 이메일·이름·전화번호·입력 내용 같은 개인정보는 모으지 않습니다. 통계 도구는 PostHog(해외 서버)입니다. 원하지 않으면 브라우저 설정에서 쿠키를 차단할 수 있습니다.

## 2. 이벤트

| 이벤트 | 언제 | 속성 |
|---|---|---|
| `$pageview` | 페이지 방문(PostHog 자동) | `service` |
| `signup` | 계정이 새로 만들어질 때 | `service` |
| `purchase` | 결제가 완료될 때 | `service`, `amount`(숫자), `currency`(ISO 통화 코드) |
| `core_action` | 서비스의 핵심 행동이 일어날 때 | `service`, `action`(= 위의 핵심 행동 값) |
| `ai_cost` | AI를 한 번 부를 때마다(서버에서) | `service`, `amount`(숫자), `currency`, `provider`, `model` |
| `$exception` | 오류(PostHog 오류 기록) | `service` |

- 해당하지 않는 이벤트는 보내지 않는다. 예: 가입이 없는 서비스는 `signup`을 보내지 않는다.
- **개인정보(이메일, 이름, 전화번호, 사용자 입력 원문)는 이벤트 속성·사용자 속성 어디에도 보내지 않는다.** 사용자를 구분해야 하면 서비스 내부의 무작위 id만 쓴다.
- `ai_cost`는 서버에서만 보낸다(브라우저에서 보내면 막히거나 조작될 수 있다).

## 3. 지표 (jelly-studio의 현황·검토·이어가기가 같은 정의를 쓴다)

- 방문자 수: `$pageview`의 고유 사용자 수
- 페이지뷰 수
- 가입 수: `signup` 개수
- 매출: `purchase`의 `amount` 합(통화별)
- 핵심 행동 수: `core_action` 개수
- AI 비용: `ai_cost`의 `amount` 합. 원으로 환산해 보여 준다
- 오류 수: `$exception` 개수

비교는 최근 14일 대 직전 14일의 변화율이다. 직전 값이 0이고 최근 값이 0보다 크면 "새로 생김", 둘 다 0이면 "–"로 보인다.
