# 인수인계

작업을 마칠 때마다 아래 세 절을 갱신한다. 절 제목은 바꾸지 않는다(jelly-studio의 현황·이어가기가 읽는다).
"다음 할 일"은 맨 위가 가장 먼저 할 일이다. 채택한 키울 아이디어(`docs/아이디어.md`)는 여기로 옮긴다.

## 마지막 작업

- 2026-10-03 PostHog 기록을 넣었다(`/crossgate` 무거움, 실행 기록 `ai-log/20261003/001_004527_posthog-tracking`). 이벤트는 `$pageview`, `core_action`(`place_open`), `$exception` 셋이고, 쿠키 고지를 첫 화면 footer에 넣었다. 동작과 사용자 결정은 [숫자 기록](숫자-기록.md) "평소보다" 절에 있다. jelly-studio 등록 문서(`jelly/register` 브랜치)도 같은 실행에서 검수했다. 아직 배포하지 않았다(배포는 `release` 브랜치에 올릴 때다).
- 2026-09-29 jelly-studio 목록에 등록했다(단계 `focus`).

## 다음 할 일

- 배포 전 운영자 확인. 둘 다 PostHog 화면에서 본다(저장소 밖): (1) 프로젝트 설정에서 방문자 IP 저장 끄기(Discard client IP data), (2) 결제 설정에서 무료 한도를 넘어도 추가 과금 없이 수집이 멈추는 상태인지. 한도에 닿으면 기록이 멈추고 숫자 누락을 허용한다.
- 배포. 사용자가 지시하면 `crossgate deploy`로 `main`을 `release`에 올린다. 배포해야 운영 화면에서 기록이 시작된다.
- 배포 뒤 숫자 확인. 운영 화면을 한 번 열고 몇 분 뒤 jelly-studio 루트에서 `python3 bin/jelly resume thanusual`을 돌려 방문자 수가 0보다 큰지 본다. 0이면 [숫자 기록](숫자-기록.md) "확인 방법"을 따른다.

## 열린 문제

- PostHog의 IP 저장 끄기와 과금 없는 한도 정지는 아직 운영자가 확인하지 않았다(위 "다음 할 일" 첫 항목).
- 방문자 수는 실제보다 적게 잡힌다. 쿠키를 차단한 브라우저에서는 PostHog를 불러오지 않고, 광고 차단기가 PostHog 요청을 막을 수 있다. 받아들인 한계다.
- PostHog 로더는 버전을 고정하지 않고 최신 SDK를 받는다(공식 로더의 동작). 숫자가 갑자기 0이 되면 SDK 쪽 설정 이름이 바뀌었는지부터 본다.
- 폭 320px 폰에서 쿠키 안내를 펼치면 그동안 목록이 약 50px로 줄어든다. 안내를 접으면 돌아온다.
